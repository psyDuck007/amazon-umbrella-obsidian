# 颜色变体广告策略

## 适用场景

用于规范 `颜色变体广告策略` 相关的广告规则。

## 输入信息

| 输入 | 来源 | 是否必需 | 备注 |
|---|---|---|---|
| 各颜色/变体广告表现 | Amazon 广告后台 / 领星 | 是 | Spend、Clicks、Orders、Sales、ACOS、CPC、CTR、CVR |
| 自然订单变化 | Seller Central / 领星 | 是 | 判断广告集中后是否带动自然流量 |
| 库存和价格 | Seller Central / 领星 | 是 | 判断主推变体是否可承接 |
| 搜索词需求 | 搜索词报告 | 是 | 确认尺寸、颜色、底座、灯光需求是否与变体匹配 |

## 已确认规则

- 如果前期有多个主卖候选变体，先用约 `7` 天广告测试比较各变体表现。
- 测试后选出数据最好的主卖变体，后续核心预算和主要广告尽量集中推该变体，用广告订单和点击信号集中权重，带动自然流量。
- 非主推变体可保留少量测试、防守、清库存或特定长尾词承接预算，但不应继续平均分散主预算。
- 判断主推变体时要综合 Orders、ACOS、CVR、CPC、CTR、Spend、自然订单和库存承接，不只看单一订单数。
- 详细结论见 [[09-规则案例与实验/06-已验证结论/广告-前期多主卖变体测试后集中推最佳变体]]。

## 条件规则

| 条件 | 动作 | 例外 |
|---|---|---|
| 多个主卖候选变体，且已完成约 `7` 天测试 | 将核心词、精准长尾词、主要预算集中到数据最好的主卖变体 | 样本不足时继续测试 |
| 搜索词明确指向某个颜色、尺寸、底座或灯光版本 | 投给能正确承接的变体 | 不为集中权重投给不匹配变体 |
| 主推变体库存不足或价格/Review 承接弱 | 暂缓集中预算，先解决承接问题 | 如果只是短期波动，可继续小额观察 |
| 非主推变体承担清库存或防守任务 | 保留少量预算 | 不与主推变体抢核心预算 |

## 禁止事项

- 不要在多个主卖变体之间长期平均分散核心预算，导致没有一个变体积累足够权重。
- 不要只看 `7` 天订单数就决定主推变体，必须结合 ACOS、CVR、CPC、CTR、库存和自然订单。
- 不要把带底座、尺寸、灯光或颜色需求明确的搜索词投给无法承接的变体。
- 不要因为集中推一个主卖变体，就完全停止所有其他变体的必要测试、防守或清库存动作。

## 输出结果

- 前期 `7` 天各主卖候选变体表现对比。
- 选定主推变体及依据。
- 需要集中预算的广告活动、广告组、投放词和广告位。
- 非主推变体保留/降预算/暂停清单。
- 集中投放后 `7-14` 天自然流量和广告效率复盘。

## 复盘指标

| 指标 | 观察周期 | 判断方式 |
|---|---|---|
| 各变体 Orders / Sales | 前期 `7` 天 | 判断直接成交能力 |
| 各变体 ACOS / CVR | 前期 `7` 天 | 判断效率和承接能力 |
| 主推变体自然订单 | 集中后 `7-14` 天 | 判断是否带动自然流量 |
| 父体总订单 | 集中后 `7-14` 天 | 判断集中策略是否带动整体增长 |
| 其他变体订单损失 | 集中后 `7-14` 天 | 判断预算集中是否副作用过大 |
| 核心词自然排名 | 集中后 `7-14` 天 | 判断权重是否改善 |

## 待验证认知

- 前期测试至少需要多少点击和订单样本，才能稳定判断主推变体。
- 非主推变体最低保留预算比例。
- 集中推一个主卖变体后，自然流量提升的标准观察窗口。
- 是否为不同颜色变体保留不同、但真实相关的场景词，能提高流量入口覆盖并维持转化。例如 Beige 测试 `outdoor`、Grey 测试 `backyard`；需按颜色变体分别记录 Impressions、CTR、CVR、Orders、CPC、ACOS 和自然订单，在 `7-14` 天或达到足够样本后判断。禁止将不匹配颜色或版本的词投向该变体。
